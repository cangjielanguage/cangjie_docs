# Compatibility Check Tool

## Overview

`cjcompat (Cangjie Compatible)` is an `ABI`/`API` compatibility check tool developed based on the Cangjie Language `Library Evolution` specification.

## Usage Instructions

Use the command line to run `cjcompat --old cjofile --new cjofile`.

`cjcompat -h` displays help information and option descriptions.

```text
Usage:
       cjcompat --old /path/to/old.cjo --new /path/to/new.cjo [--api] [--abi] [--import-path /path]
Options:
   -h                      Show usage
                               eg: cjcompat -h
   --old <value>           Path to the .cjo file corresponding to the old version of a Cangjie library.
   --new <value>           Path to the .cjo file corresponding to the new version of a Cangjie library.
                               eg: cjcompat --old filePathOld --new filePathNew
   --import-path <value>   Add .cjo search path.
   --api                   Enforces rules for API compatibility.
   --abi                   Enforces rules for ABI compatibility.
                               eg: cjcompat --old filePathOld --new filePathNew --api
```

### Compatibility Rule Check

`cjcompat --old cjofile --new cjofile`

- Checks whether `cjo` files of different versions are compatible. The `cjofile` supports both relative and absolute paths.

```shell
cjcompat --old old.cjo --new new.cjo
```

> **Note:**
>
> When performing rule checks, the `--old` and `--new` options must be specified and may appear only once; otherwise an error is reported.
> The `cjofile` of different versions must end with `.cjo`; otherwise an error is reported.
> The `cjofile` of different versions must be generated by `cjc` from compatible versions; otherwise `cjo` file parsing errors may occur due to version incompatibility.
> When no check rule type is specified, both the `api` and `abi` rules are checked by default.
> If the error `Cannot load file old.cjo` occurs, it may depend on other `cjo` files. You can specify the path to the dependent `cjo` files using the `CANGJIE_PATH` environment variable or `--import-path`.

### API Compatibility Rule Check

`cjcompat --api`

- The `--api` option lets the user specify that only the `api` compatibility rules are checked.

```shell
cjcompat --old old.cjo --new new.cjo --api
```

### ABI Compatibility Rule Check

`cjcompat --abi`

- The `--abi` option lets the user specify that only the `abi` compatibility rules are checked.

```shell
cjcompat --old old.cjo --new new.cjo --abi
```

## Compatibility Rules

For specific compatibility rules, please refer to the Cangjie Module Evolution Compatibility Specification `(library evolution spec)`.

The compatibility rules for adding and deleting global variables are as follows:

| Change Behavior | `API` Compatibility | `ABI` Compatibility |
|-|-|-|
| Adding a global variable | Compatible | Compatible |
| Deleting a global variable without the `public` modifier | Compatible | Compatible |
| Deleting a global variable with the `public` modifier | Incompatible | Incompatible |

Examples based on the above compatibility rules are as follows:

【Correct Example】

<!-- code_no_check -->

```cangjie
// old.cj
package A

public var x: Int64 = 10

//==================================//

// new.cj
package A

public var x: Int64 = 10
var y: Int64 = 10 // Adding a global variable
```

Use this tool to perform a rule check on the `cjo` file generated from the above Cangjie source code.

```shell
cjcompat --old old.cjo --new new.cjo
```

The result is as follows:

```text
Compatible!
```

> **Explanation:**
>
> Adding a global variable, the check result is that both `API` and `ABI` are compatible.

【Correct Example】

<!-- code_no_check -->

【Incorrect Example】

```cangjie

  var_decl y: [BEFORE] A/new.cj:4:1-4:25
```

> **Explanation:**
>
> Deleting a global variable with the `public` modifier, the check result is that both `API` and `ABI` are incompatible.
